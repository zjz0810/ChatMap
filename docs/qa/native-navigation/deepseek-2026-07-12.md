# DeepSeek Browser QA

- Date: 2026-07-13
- Result: `blocked-auth`
- Page result: a fresh anonymous browser session at `https://chat.deepseek.com/` redirected to `https://chat.deepseek.com/sign_in`; no credentials or challenge bypass were used.
- Extension result: the unpacked TurnMap build loaded and injected exactly one page launcher.
- Production-contract result: the current DeepSeek frontend requests `/api/v0/chat/history_messages`; its response exposes `chat_session.current_message_id`, ordered `chat_messages`, stable `message_id` / `parent_id`, roles, and typed fragments. The production virtual list is keyed by the same message identity and exposes an exact keyed `scrollTo` route.
- Implementation result: TurnMap now passively captures that structured history, derives only the active parent chain, excludes `THINK` fragments from answers, enriches streaming content without changing identities, and invokes the exact keyed virtual-list route only after a user navigation action. Remount is accepted only when the exact `[data-virtual-list-item-key]` appears; there is no text matching or scroll search fallback.
- Automated evidence: `tests/deepseek-native-navigation.test.mjs` covers full history, repeated prompts, branch selection, thinking exclusion, streaming enrichment, conversation isolation, exact off-screen targeting/remount, wrong-ID/timeout failure, adapter routing, and the no-passive-scroll boundary.
- Capability decision: keep `blocked-auth` and the mounted-DOM capability tier. The implementation is complete, but no authenticated long conversation was available to prove end-to-end off-screen navigation in the live account UI, so no native promotion is claimed.
