## 2026-07-13 Native-index adaptation

- Implementation: a clean-room `document_start` MAIN-world observer passively captures Qwen's existing `GET /chats/:id` response. The content adapter follows `history.currentId` through `parentId`, builds stable conversation/user-message navigation identities, and performs no extraction scrolling.
- Identity and branching: identical prompt text remains separate by user message ID. Streaming updates enrich the same assistant response without changing the user turn navigation ID; an explicit regenerated response ID replaces the prior active branch instead of leaking stale branch content.
- Complete-index behavior: structured history remains authoritative when early `.chat-round[data-chat]` elements are absent. Exact mounted DOM text may enrich only the native turn with the same `data-chat` identity.
- Navigation safety: an exact mounted `data-chat` or `data-message-id` round is revealed directly. No deterministic Qwen virtual-item controller was verified, so an unmounted, missing, or mismatched target returns an explicit failure without text similarity, offset guessing, or scroll search.
- Automated evidence: synthetic fixtures cover complete history, repeated prompt identity, streamed placeholder enrichment, early unmounted retention, active regeneration branches, SPA conversation isolation, exact mounted navigation, safe failure, adapter routing, and eager passive capture.
- Browser boundary: the prior anonymous repeated-prompt smoke remains valid. The current public Qwen bundle exposed `GET /chats/:id`, `history.messages`, `currentId`, `parentId`, stable message IDs, and response branch IDs, while the current guest page required login for fresh conversation evidence. A policy-verifiable authenticated 20-turn/off-screen run was not available.
- Capability decision: retain `smoke-verified` at the mounted-DOM tier. The structured native index is implemented and evidence-gated, but off-screen deterministic remount and long-conversation acceptance are not promoted.
